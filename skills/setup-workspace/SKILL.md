# Est Rouge CMS 初回導入（/setup-workspace）

編集者（エンジニアではない人）が、Est Rouge CMS をパソコンに取り込む（Clone する）ところまでを手伝う Skill です。
確認と Clone は補助スクリプト `scripts/setup.sh` が行います。あなたの役割は、スクリプトの実行と、結果の分かりやすい案内です。

- やり取りはすべて日本語。専門用語は避け、使う場合はひとことで言い換える（例: 「Clone（CMS 一式をパソコンに取り込むこと）」）。
- 一度にたくさんの指示を出さず、1 ステップずつ進める。
- 詳しい案内文やトラブル対応は `references/setup-guide.md` にある。必要になったら読む。

## スクリプトの場所と実行方法

スクリプトは、この SKILL.md と同じフォルダの `scripts/setup.sh` です。必ず `bash` で実行します（ZIP 展開時に実行権限が失われても動くようにするため）。

```
bash "${CLAUDE_SKILL_DIR}/scripts/setup.sh" <サブコマンド> [保存先]
```

`${CLAUDE_SKILL_DIR}` が置き換えられていない場合は、この Skill のベースディレクトリ（SKILL.md があるフォルダ）の絶対パスを使う。
カレントディレクトリや別リポジトリのスクリプトに頼らないこと。

| サブコマンド | 内容 | 変更の有無 |
|---|---|---|
| `check` | macOS・Git・gh・ログイン状態・アカウント・リポジトリ権限を確認 | なし |
| `accounts` | この Mac でログイン済みの GitHub アカウントの一覧 | なし |
| `switch <アカウント>` | ログイン済みの別アカウントに切り替え、権限を再確認 | 使用中のアカウントの切り替え（**承認後のみ**） |
| `login` | ブラウザでの GitHub ログインを開始し、完了を待って権限を再確認 | アカウントの追加（**承認後のみ**） |
| `suggest` | おすすめの保存先を表示 | なし |
| `plan <保存先>` | 保存先が使えるか確認 | なし |
| `clone <保存先>` | Clone（正しい Clone が既にあれば再利用） | 新しいフォルダの作成のみ |
| `verify <保存先>` | Clone 済みフォルダの確認 | なし |

出力の最後の `KEY=value` 行（特に `RESULT=`）で結果を判定する。終了コード: `0` 成功 / `1` 利用者の対応が必要 / `2` 失敗 / `3` 保存先が使えない / `64` 使い方の誤り。
**終了コードが 0 以外のときは、決して「完了しました」と伝えない。**

## 手順

### 1. 準備状況の確認

`check` を実行し、`RESULT` に応じて進める。

- `READY` → 「GitHub のアカウント「(ACCOUNT)」を使います。CMS 用のアカウントで合っていますか？」と確認する。
  合っていれば手順 2 へ。違う場合は「1-2. GitHub アカウントの調整」へ。
- `UNSUPPORTED_OS` → Mac 以外は未対応であることを伝えて終了。
- `NEED_INSTALL` → `MISSING`（git / gh）と `BREW`（Homebrew の有無）に応じて、`references/setup-guide.md`「ソフトの追加」の案内をする。
  - インストールは**必ず内容（何を・どのコマンドで・何のために）を説明し、ユーザーが明示的に「お願いします」等と了承してから**行う。了承がなければ実行しない。
  - あなたが実行してよいのは `brew install git` / `brew install gh` のみ（了承後）。
  - Homebrew 本体のインストールや `xcode-select --install` はパスワード入力や画面操作が必要なので、ユーザー自身に「ターミナル」アプリで実行してもらう。インターネット上のスクリプトをあなたが取得して実行しない。
  - 終わったら `check` をやり直す。
- `NEED_LOGIN` → 「1-2. GitHub アカウントの調整」へ。
- `NO_REPO_ACCESS` → 「アカウント「(ACCOUNT)」では CMS を見る権限がありません」と伝え、「1-2. GitHub アカウントの調整」へ。
- `NETWORK_ERROR` → インターネット接続を確認してもらい、`check` をやり直す。
- その他・`UNEXPECTED_ERROR` → 出力を要約して伝え、担当者への相談を勧める。

### 1-2. GitHub アカウントの調整（切り替え・新規ログイン）

アカウントの確認・切り替え・ログイン開始は、この画面（Code タブ）の中であなたがスクリプトで行う。
編集者にしてもらうのは **アカウントの選択・操作の承認・ブラウザでのログインと承認** だけ。ターミナルでの操作は、下の「手動での対応」が必要な場合に限る。

1. `accounts` を実行し、この Mac でログイン済みのアカウントを確認する（変更なし）。
   - `RESULT=AUTH_UNSUPPORTED`（古い gh）→ 「手動での対応」へ。
2. 編集者にどのアカウントを使うか選んでもらう（選択肢を示せる場合は選択式でたずねる）:
   - `KNOWN_ACCOUNTS` の各アカウント（使用中のものはそう示す）
   - 「別のアカウントで新しくログインする」
   - 使用中のアカウントが選ばれたら、何も変更せずに手順 1 の結果に戻る（`NO_REPO_ACCESS` なら、そのアカウントでは続けられないことを伝える）。
3. **ログイン済みの別アカウントに切り替える場合**
   1. 実行前に承認を得る: 「使用する GitHub アカウントを『(現在)』から『(選んだもの)』に切り替えます。『(現在)』のログインは残ったままで、いつでも戻せます。切り替えてよろしいですか？」
   2. 明確な了承を得たら `switch <選んだアカウント>` を実行する。了承がなければ実行しない。
   3. 結果は下の「切り替え・ログイン後の結果」で判定する。
4. **新しいアカウントでログインする場合**
   1. 実行前に、流れを説明して承認を得る（`references/setup-guide.md`「画面内でのログイン」の案内文を使う）。要点:
      - ブラウザで GitHub の確認ページが自動で開く
      - 確認用のコードは自動でクリップボードにコピーされる（画面には表示しない）。ページの入力欄に `command` + `V` で貼り付ける
      - ブラウザで、CMS 用のアカウントでログインしていることを確認し、「Authorize」で承認する
      - 最大 9 分待つ。この間、こちらの画面は待機状態になる
      - 既存のアカウントのログインは残る
   2. 明確な了承を得たら `login` を実行する（Bash のタイムアウトは 600000ms）。了承がなければ実行しない。
   3. 結果は下の「切り替え・ログイン後の結果」で判定する。
5. **切り替え・ログイン後の結果**（スクリプトが使用中のアカウントとリポジトリへのアクセスを再確認している）
   - `RESULT=READY` → 「アカウント『(ACCOUNT)』で CMS にアクセスできることを確認しました」と伝え、手順 2（保存先が決まっていれば手順 3 の Clone）を再開する。
   - `RESULT=NO_REPO_ACCESS` → そのアカウントには CMS を見る権限がないことを伝える。別のアカウントを選ぶか、管理者への招待依頼を案内する（`references/setup-guide.md`「リポジトリにアクセスできない」）。
   - `LOGIN_DENIED` / `LOGIN_EXPIRED` / `LOGIN_TIMEOUT` → 理由を伝え、「もう一度ログインを始めますか？」とたずねる。再試行も改めて了承を得てから。
   - `ACCOUNT_NOT_FOUND` / `ACCOUNT_NEEDS_LOGIN` → そのアカウントは新しくログインし直す必要があると伝え、手順 4 を提案する。
   - `SWITCH_FAILED` / `LOGIN_FAILED` / `NETWORK_ERROR` → スクリプトが示した理由を伝え、再試行（了承を得てから）か「手動での対応」を案内する。
   - `LOGIN_UNSUPPORTED` / `AUTH_UNSUPPORTED` → この画面からは安全に操作できないため、「手動での対応」へ。
   - どの場合も、`RESULT=READY` が出るまでは「ログインできました」「切り替えました」と伝えない（`ACTION=switched` / `logged_in` でも、権限がなければ完了ではない）。
6. **手動での対応（自動でできない場合のみ）**: `references/setup-guide.md`「手動でのログイン・切り替え」を案内する。編集者が終わったと言ったら `check` をやり直す。

### 2. 保存先を決める

1. 「CMS をどこに保存しますか？」とたずねる。分からない・おまかせと言われたら `suggest` を実行し、表示された場所（ホームフォルダ内の `EstRouge/est-rouge-cms-demo`）を提案する。
   保存先の候補をあなたが勝手に作らない。固定のユーザー名やパス（例: `/Users/xxx`）を推測で書かない。
2. ユーザーの答えを `plan` に渡す（`~/…` の形でもフルパスでもよい）。
   - 指定した場所の最後のフォルダ名が `est-rouge-cms-demo` でなければ、その中に `est-rouge-cms-demo` フォルダが作られる（スクリプトが自動で決める。出力の `DEST=` が最終的な保存先）。
3. `plan` の結果:
   - `STATE=absent` / `empty` → 手順 3 へ。
   - `STATE=reuse` → 「既に正しく取り込まれているので、そのまま使います」と伝えて手順 3 へ（clone を実行しても再利用されるだけ）。
   - `RESULT=DEST_CONFLICT`（`other-repo` / `plain-dir` / `not-directory` / `broken-repo` / `incomplete-repo`）→ そのフォルダには触らないことを伝え、別の保存先をたずねて 2 からやり直す。
   - `RESULT=INVALID_DEST` → 理由を伝え、ホームフォルダ内の別の場所をたずねる。

### 3. Clone の実行

1. 実行前に、次の 2 点をユーザーに提示して了承を得る:
   - 取り込むもの: `https://github.com/erj-haru/est-rouge-cms-demo.git`
   - 保存先: `plan` の `DEST=` の値
2. 了承後に `clone <保存先>` を実行する（Bash のタイムアウトは 600000ms）。
3. 結果:
   - `RESULT=CLONED` または `RESULT=REUSED`（終了コード 0）→ 手順 4 へ。`LOCAL_CHANGES` が 1 以上なら、「保存されていない変更がありますが、消さずに残しています」と添える。
   - `RESULT=CLONE_FAILED` → スクリプトが示した「原因」「対処」を、そのまま分かりやすく伝える。
   - `RESULT=VERIFY_FAILED` → 取り込んだ内容に問題があったことを伝え、フォルダは削除していないこと、担当者に相談することを案内する。
   - `RESULT=DEST_CONFLICT` → 手順 2 に戻る。

### 4. 完了の案内

`references/setup-guide.md`「完了時の案内」の形で、次の 4 点を伝える:

1. Clone したフォルダの場所（`DEST=` の値）
2. Claude Desktop の「Code」タブで、そのフォルダを開く方法
3. フォルダを開いたら、CMS の `/setup-editor` を実行すること
4. セットアップ後は `/cms-help` で使い方を確認できること

## 守ること

- **認証情報を扱わない。** パスワード・トークン・認証コードを尋ねない、貼り付けを求めない。`gh auth token` や `gh auth status --show-token` など、トークンを表示するコマンドを実行しない。
  ユーザーが貼り付けてしまった場合は、その値を繰り返さず、無効化（再発行）を勧める。
- **アカウントの切り替え・ログインは、毎回明確な承認を得てから、スクリプトの `switch` / `login` だけで行う。** `gh auth switch` / `gh auth login` を直接実行しない（スクリプトはコードを隠し、結果を再確認するため）。
- **ログアウトしない。** `gh auth logout` は絶対に実行しない。既存アカウントのログインは常に残す。
- **ブラウザでのログイン・承認は本人が行う。** あなたがブラウザを操作して GitHub にログインしたり承認したりしない。
- **確認用コードを見ない・表示しない。** `pbpaste` などでクリップボードを読まない。コードを教えてほしいと頼まない。
- **既存のファイル・フォルダを削除・上書きしない。** `rm -rf`、`git reset --hard`、`git clean`、`git checkout -- .`、`git stash` などを実行しない。
- **既存のリポジトリを変更しない。** 再利用する場合でも `git pull` / `git fetch` / `git commit` / `git push` をしない。
- **コミット・Push・PR 作成をしない。** CMS 本体のファイルも編集しない。
- **了承のないインストールをしない。** インターネットから取得したスクリプトを実行しない。
- **Docker・Astro・プレビュー・記事の作成や公開は扱わない。** それらは Clone 後に CMS 側の `/setup-editor` 以降の Skill が担当する。
- スクリプトの結果と異なる内容（失敗したのに成功したなど）を伝えない。
