# /setup-workspace 案内文とトラブル対応

SKILL.md の手順から参照する、編集者向けの案内文集です。
状況に合う部分だけを、1 ステップずつ伝えてください。コマンドは、ユーザーがコピーしやすいようにコードブロックで示します。

---

## ターミナルの開き方

いくつかの作業は、Mac の「ターミナル」アプリでご本人に行っていただきます。

1. キーボードで `command` + `space` を押して Spotlight 検索を開く
2. 「ターミナル」と入力して `return` を押す
   （または Finder →「アプリケーション」→「ユーティリティ」→「ターミナル」）
3. 開いた画面に、案内したコマンドを貼り付けて `return` を押す

## ソフトの追加

CMS を取り込むには、次の 2 つのソフトが必要です。

- **Git**: ファイルの変更履歴を管理するソフト
- **GitHub CLI（gh）**: GitHub とやり取りするためのソフト

### A. Homebrew がある場合（`BREW=yes`）

Homebrew（Mac にソフトを追加するための道具）を使って追加できます。
**ユーザーに次の内容を説明し、了承を得てから** 実行してください（了承がなければ、ユーザー自身にターミナルで実行してもらう）。

- 不足が Git の場合: `brew install git`
- 不足が gh の場合: `brew install gh`
- 両方の場合: `brew install git gh`

説明の例:

> GitHub CLI（gh）というソフトが入っていないため、追加が必要です。
> Homebrew を使って `brew install gh` を実行し、インストールします。数分かかることがあります。
> 実行してよろしいですか？

インストール後は `check` をもう一度実行して確認します。

### B. Homebrew がない場合（`BREW=no`）

Homebrew 本体のインストールには Mac のパスワード入力が必要なため、**ご本人にターミナルで行っていただきます**。
あなた（Claude）がインターネット上のインストール用スクリプトを取得・実行してはいけません。

案内の例:

> Mac にソフトを追加するための「Homebrew」が入っていません。次の手順でインストールしてください。
> 1. ブラウザで公式サイト https://brew.sh/ja/ を開く
> 2. ページ上部に書かれている「インストール」のコマンドをコピーする
> 3. ターミナルに貼り付けて `return` を押し、表示に従う（途中で Mac のログインパスワードを求められます。入力中は文字が表示されませんが、そのまま入力して `return` を押してください）
> 4. 最後に「Next steps」と表示された場合は、そこに書かれたコマンドもターミナルで実行する
> 5. 終わったら「終わりました」と教えてください

Homebrew が入ったら、A の手順に進みます。

Homebrew を使いたくない場合の代わりの方法:

- **Git**: ターミナルで `xcode-select --install` を実行すると、Apple の「コマンドライン・デベロッパツール」のインストール画面が出ます。「インストール」を押して完了を待ちます。
  （Git を実行しようとした時に、同じ画面が自動で出ることもあります。）
- **gh**: 公式の配布ページ https://github.com/cli/cli/releases/latest から、`macOS` 用の `.pkg` ファイルをダウンロードし、ダブルクリックしてインストールします。

## GitHub アカウントの選択

`accounts` の結果をもとに、どのアカウントを使うかを選んでもらいます。

> この Mac では、次の GitHub アカウントでログインしたことがあります。CMS で使うアカウントを選んでください。
> - alice（使用中）
> - bob
> - 別のアカウントで新しくログインする

- 会社から CMS 用として案内されたアカウントを選んでもらいます。分からない場合は管理者に確認してもらいます。
- 一覧が空の場合は、「新しくログインする」流れに進みます。

## 画面内でのアカウント切り替え

ログイン済みの別のアカウントに切り替える場合です。**必ず承認を得てから** `switch <アカウント>` を実行します。

承認のお願いの例:

> 使用する GitHub アカウントを「alice」から「bob」に切り替えます。
> 「alice」のログインは残ったままなので、あとで元に戻すこともできます。
> 切り替えてよろしいですか？

結果の伝え方の例:

- `RESULT=READY`: 「アカウントを『bob』に切り替え、CMS にアクセスできることを確認しました。続けて CMS の取り込みに進みます。」
- `RESULT=NO_REPO_ACCESS`: 「『bob』に切り替えましたが、このアカウントには CMS を見る権限がありませんでした。別のアカウントを選ぶか、管理者に招待を依頼してください。」

## 画面内でのログイン

新しいアカウントでログインする場合（未ログイン・有効期限切れを含む）です。**必ず流れを説明し、承認を得てから** `login` を実行します。
`login` の実行中、こちらの画面は承認の完了を待つ状態になるため、**開始前に** ブラウザでの手順を伝えておきます。

承認のお願いの例:

> GitHub へのログインを始めます。流れは次のとおりです。
> 1. ブラウザで GitHub の確認ページが自動で開きます
> 2. 確認用のコード（8 文字）は、自動でクリップボードにコピーされます。安全のため、この画面には表示しません
> 3. GitHub にログインしていない場合は、CMS 用のアカウントでログインしてください。
>    すでに別のアカウントでログインしている場合は、右上のアイコンから CMS 用のアカウントに切り替えてください
> 4. コードの入力欄をクリックし、`command` + `V` で貼り付けて「Continue」を押します
> 5. 「Authorize github」（GitHub CLI の許可）の画面で、緑色の「Authorize」ボタンを押します
> 6. 「Congratulations, you're all set!」と表示されたら完了です。この画面に戻ってきてください
>
> ブラウザが自動で開かない場合は、ご自身で https://github.com/login/device を開いてください。
>
> 最大 9 分お待ちします。今あるアカウントのログインはそのまま残ります。
> パスワードやコードをこのチャットに入力する必要はありません。
> ログインを始めてよろしいですか？

結果の伝え方の例:

- `RESULT=READY`: 「ログインが完了し、アカウント『(ACCOUNT)』で CMS にアクセスできることを確認しました。続けて CMS の取り込みに進みます。」
- `LOGIN_DENIED`: 「ブラウザで許可がキャンセルされたようです。もう一度ログインを始めますか？」
- `LOGIN_EXPIRED` / `LOGIN_TIMEOUT`: 「時間内に許可が完了しなかったため、いったん中止しました。もう一度始めますか？（新しいコードが用意されます）」
- `BROWSER_OPENED=no` だった場合: `login` の実行中は会話できないため、再試行するときの事前の案内に「ブラウザが自動で開かない場合は、ご自身で https://github.com/login/device を開いてください」と加える

注意:

- 確認用のコードは一回限りで、数分で使えなくなります。チャットに貼り付けないでください。もし貼り付けてしまっても、コードを繰り返し表示しないでください。
- 安全のため、ログイン終了後にクリップボードに残ったコードは自動で消去されます。

## 手動でのログイン・切り替え

**画面内で操作できない場合だけ**（`LOGIN_UNSUPPORTED` / `AUTH_UNSUPPORTED`、または再試行しても失敗する場合）の方法です。
コードやパスワードは、ご本人のターミナルとブラウザの中だけで扱われ、Claude には伝わりません。

新しくログインする場合:

> 1. 「ターミナル」アプリを開き（上の「ターミナルの開き方」）、次のコマンドを貼り付けて `return` を押してください
>    ```
>    gh auth login --hostname github.com --git-protocol https --web
>    ```
> 2. 「Authenticate Git with your GitHub credentials?」と聞かれたら `Y` を押して `return`
> 3. 「First copy your one-time code: XXXX-XXXX」と表示されたら、その 8 文字のコードを控えて `return` を押す（ブラウザが開きます）
> 4. ブラウザでコードを入力し、「Authorize（許可）」を押す
> 5. ターミナルに「Logged in as …」と表示されたら完了です。「終わりました」と教えてください

ログイン済みの別アカウントに切り替える場合:

> ターミナルで次のコマンドを実行してください（`アカウント名` は使うアカウントに置き換えます）
> ```
> gh auth switch --hostname github.com --user アカウント名
> ```

`gh` が古いために画面内で操作できない場合は、Homebrew がある環境なら `brew upgrade gh` で更新すると、画面内での操作ができるようになります（更新も、内容を説明し了承を得てから）。

終わったら `check` をもう一度実行して、使用中のアカウントと CMS へのアクセスを確認します。

## リポジトリにアクセスできない（`NO_REPO_ACCESS`）

> アカウント「(ACCOUNT)」では、CMS のリポジトリを見ることができませんでした。
> - CMS 用のアカウントでログインしているか確認してください（違う場合は、ログイン済みの別アカウントへの切り替えか、新しいログインをこの画面で行えます）
> - 管理者から GitHub の招待メールが届いている場合は、メール内のリンクから招待を承認してください
> - 招待がまだの場合は、管理者に「erj-haru/est-rouge-cms-demo へのアクセス権」を依頼してください

## 保存先の決め方

- おすすめは、ホームフォルダの中の `EstRouge/est-rouge-cms-demo` です（`suggest` で表示される場所）。
- 「書類（Documents）」や「デスクトップ」は、iCloud の同期対象になっていることがあり、同期でファイルが一時的に見えなくなることがあるため、おすすめしません。
- 次の場所は使えません: ホームフォルダの外、「Library」「Applications」の中、名前が「.」で始まる隠しフォルダ。
- 指定した場所に既に別のファイルやフォルダがある場合、上書きせずに止まります。別の場所を指定してください。

## 完了時の案内

次の形でお伝えください（`(DEST)` は `clone` の出力の `DEST=` の値）。

> ✅ CMS の取り込みが完了しました。
>
> **1. 保存場所**
> `(DEST)`
>
> **2. Claude Desktop でこのフォルダを開く**
> 1. Claude Desktop の「Code」タブを開きます
> 2. 新しいセッションを始めるときに、作業するフォルダとして上の保存場所（`est-rouge-cms-demo` フォルダ）を選びます
>    （Finder で探す場合: Finder のメニュー「移動」→「フォルダへ移動…」に上の場所を貼り付けると開けます）
>
> **3. 記事を書く準備をする**
> 開いたセッションで `/setup-editor` を実行してください。プレビュー環境の確認と起動を行います。
>
> **4. 使い方を確認する**
> 準備ができたら、`/cms-help` でこの CMS の使い方を確認できます。

補足:

- 既存のフォルダを再利用した場合（`RESULT=REUSED`）は、「以前取り込んだフォルダをそのまま使います（内容の更新はしていません）」と添えてください。
- Code タブの画面の名称や配置は、Claude Desktop のバージョンによって異なる場合があります。

## トラブル対応

| 状況 | 原因の例 | 対処 |
|---|---|---|
| Git を実行すると「コマンドライン・デベロッパツール」の画面が出る | Git がまだ入っていない | 画面の「インストール」を押して完了を待ち、`check` をやり直す |
| `brew install` が失敗する | ネット接続、Homebrew の不調 | 接続を確認して再実行。解決しない場合は「Homebrew を使いたくない場合の代わりの方法」へ |
| インストールしたのに「見つかりません」と出る | Claude Desktop が古い設定のまま | Claude Desktop を終了して開き直し、もう一度 `/setup-workspace` を実行 |
| ログインしたのに `NEED_LOGIN` になる | ログインの有効期限切れ | 「画面内でのログイン」をもう一度行う |
| `NO_REPO_ACCESS` | アカウント違い・招待未承認 | 「GitHub アカウントの選択」から切り替えるか、上の「リポジトリにアクセスできない」を参照 |
| ブラウザが開かない | ブラウザの設定・制限 | ブラウザで https://github.com/login/device を開き、`command` + `V` でコードを貼り付ける |
| コードを貼り付けられない／無効と表示される | クリップボードが上書きされた・期限切れ | ログインをもう一度始める（新しいコードがコピーされる） |
| ブラウザで違うアカウントを許可してしまった | ブラウザで別アカウントにログインしていた | 再確認の結果に表示されたアカウント名を確認し、「GitHub アカウントの選択」からやり直す |
| `LOGIN_UNSUPPORTED` / `AUTH_UNSUPPORTED` | gh が古い・画面内で安全に操作できない | 「手動でのログイン・切り替え」へ |
| Clone に失敗（接続） | インターネットに接続できない | Wi-Fi・VPN を確認して再実行 |
| Clone に失敗（権限） | アカウントにリポジトリの権限がない | 「GitHub アカウントの選択」から別のアカウントを使うか、管理者に招待を依頼 |
| Clone に失敗（容量） | Mac の空き容量不足 | 空き容量を増やして再実行 |
| 保存先が使えない（`DEST_CONFLICT`） | 同じ名前の別のフォルダがある | そのフォルダはそのままにして、別の保存先を指定 |
| 取り込み後の確認に失敗（`VERIFY_FAILED`） | 取り込んだ内容が想定と違う | フォルダは削除していない。担当者に出力内容を伝える |

何度実行しても安全です。途中で止まった場合は、もう一度 `/setup-workspace` を実行してください（正しく取り込み済みのフォルダは再利用されます）。
